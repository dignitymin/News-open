# 전국 부동산 데일리 브리핑 (매일)

- 루틴 이름: `전국 부동산 데일리 브리핑`
- cron (UTC): `0 22 * * *` (= 매일 KST 07:00)
- model: `claude-sonnet-5`
- repo: `https://github.com/dignitymin/News-open`
- allowed_tools: `Bash, Read, Write, Edit, Glob, Grep, WebFetch, WebSearch`
- 대상 파일: 저장소 루트의 `latest.json`

## 프롬프트

저장소 https://github.com/dignitymin/News-open 의 루트에 있는 latest.json 파일을 오늘자 '전국 부동산 데일리 브리핑'으로 갱신하고 커밋/푸시하라.

### 목표
매일 아침 전국 부동산 관련 주요 뉴스를 검색해 중요도·화제성 기준 상위 기사(최대 10건)를 선별하고, 아래 스키마의 JSON으로 latest.json을 덮어쓴 뒤 main 브랜치에 커밋/푸시한다.

### 절차
1. 현재 UTC 시각에 9시간을 더해 오늘 날짜(Asia/Seoul, KST)를 구한다. 이 날짜를 "date" 필드와 커밋 메시지에 사용한다.
2. WebSearch로 최근 24~48시간 내 한국 부동산 관련 뉴스를 다양한 키워드로 검색한다 (예: 아파트 가격, 부동산 정책, 재건축·재개발, 분양·청약, 전월세, 대출·금리, 강남/수도권/지방 부동산 등). 여러 번의 검색으로 후보 기사를 폭넓게 수집한다.
3. 후보 중 전국적 파급력·화제성이 큰 순서로 최대 10건을 고른다. 확실히 기준을 충족하는 기사가 10건 미만이면 억지로 채우지 말고 그 수만큼만 싣는다 (과거 사례: 6~7건만 실은 적 있음).
4. 각 후보 기사는 반드시 실제 게재일을 확인한다. 우선 WebFetch로 기사 원문에 접속해 게재일과 핵심 내용을 확인한다. 만약 이 실행 환경의 네트워크 정책 때문에 WebFetch가 막히거나 실패하면, WebSearch 결과에 표시되는 게재일/스니펫 정보를 대신 근거로 사용해도 된다 (단, 이 경우도 날짜가 합리적으로 확인되는 기사만 포함). 두 방법 모두로도 게재일을 전혀 특정할 수 없는 기사는 포함하지 않는다.
5. 게재일이 오늘 기준 대략 3일 이상 지난(오래된) 기사, 특히 연도가 다른(예: 작년 기사가 최신으로 오인되는) 기사는 절대 포함하지 않는다.
6. 선정된 각 기사에 대해 한국어로 2~3문장의 객관적 요약을 작성한다.

### latest.json 스키마 (repo 루트, 2-space indent, UTF-8, 한글 그대로 표기 — 이스케이프하지 말 것)

```json
{
  "date": "YYYY-MM-DD",
  "title": "전국 부동산 데일리 브리핑",
  "items": [
    {
      "rank": 1,
      "headline": "기사 제목",
      "summary": "2~3문장 한국어 요약",
      "source": "언론사명",
      "publishedDate": "YYYY-MM-DD",
      "url": "기사 원문 URL"
    }
  ],
  "note": "선정 기준을 충족한 기사가 10건 미만이면 그 사유를 짧게 설명. 검증 가능한 기사가 아예 없으면 items를 빈 배열로 두고 그 사유(예: 네트워크 제약 등)를 구체적으로 설명."
}
```

### 절대 규칙
- URL, 언론사, 게재일, 기사 제목·내용을 절대 지어내지 않는다. 실제로 WebSearch/WebFetch로 확인된 기사만 싣는다.
- 검증 가능한 기사가 하나도 없더라도 latest.json 자체는 반드시 오늘 날짜로 갱신해서 커밋한다 (items: [], note에 사유 명시).
- 기존 파일 포맷(필드명, 구조)을 그대로 유지한다. latest.json 외 다른 파일은 만들지 않는다.

### 커밋
`git add latest.json` 후 `git commit -m "Update latest.json (YYYY-MM-DD)"` (오늘 날짜), main 브랜치로 push.
